# Java 작업 규정

- 명확한 타입을 우선 사용하고 불필요한 Object 타입 사용을 피한다
    - var 키워드를 사용하지 않는다
    - 제네릭과 타입 추론을 적절히 활용하여 불필요한 형 변환을 피한다
    - Object 타입은 동적 구조가 반드시 필요한 경우에만 사용하고 사용 이유를 설명한다
- API 요청/응답, 도메인 모델 및 서비스 간 데이터 전달에는 구체적인 타입의 DTO나 모델을 사용한다
- 필드/메서드에 주석을 작성할 때에는 Javadoc 형식으로 작성한다
- 새 코드에서 Deprecated로 표시된 API를 사용하지 않는다
    - 기존 Deprecated API를 수정할 때는 대체 API와 호환성을 확인한다
    - 대체 API가 없거나 마이그레이션 위험이 있으면 근거를 설명한다
- 프로젝트에서 사용하는 Java 25의 안정화된 언어 기능을 적절히 활용한다
    - 최신 문법을 사용하기 위해 불필요하게 코드를 복잡하게 만들지 않는다
    - 기존 코드와의 일관성, 가독성 및 팀의 유지보수성을 우선한다
    - 미리보기 (Preview) 기능은 별도 승인 없이 도입하지 않는다
